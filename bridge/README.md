# N6 → Jetson bridge

מעביר את פריימי המצלמות (תרמי + RGB) ואת דגימות ה-IMU מלוח ה-N6 אל הג'ייסון
דרך ה-USB, בפורמט בינארי עם מספר רץ, חותמת זמן ו-CRC לכל הודעה — כדי שההיתוך
על הג'ייסון (ושכבת ה-IMU של יעל) יקבלו נתונים שאפשר לסמוך עליהם, וכל אובדן
ייספר במקום להיעלם בשקט.

| קובץ | תפקיד |
|---|---|
| `bridge_protocol.h` | **החוזה** — מבנה ההודעה, לצד ה-C |
| `bridge_protocol.py` | אותו חוזה לפייתון (רץ גם על ה-N6 וגם במחשב) + `Decoder` |
| `n6_bridge_tx.py` | השולח — רץ **על ה-N6**. `Bridge` = ליבה בלי חומרה, `main()` = החיבור לחיישנים |
| `n6_bridge_start.py` | משגר — דוחף את השולח ל-N6 (raw REPL). עם `--record` גם מקליט ומדפיס סטטיסטיקה |
| `bridge_rx.c` | המקלט — רץ **על הג'ייסון** ב-C. פותח לקריאה בלבד, לא משדר לעולם |
| `test_*.py` | בדיקות: חוזה, שולח, מקלט (pty + קובץ, גם בבניית ASan) |

## הרצה
```
make test                                   # בונה + כל הבדיקות, בלי חומרה
python3 n6_bridge_start.py --record s.bin --seconds 10   # בדיקה חיה + הקלטה
./bridge_rx s.bin -o out/                   # replay ההקלטה במקלט ה-C
python3 n6_bridge_start.py && ./bridge_rx /dev/serial/by-id/usb-MicroPython_Pyboard* -o out/   # חי
```
`out/` יכיל `<seq>_thermal.bin` / `<seq>_rgb.bin` (הנתונים כפי שנשלחו) ו-`imu.csv`
עם חותמות זמן **פרוסות** (בלי גלישה).

## תצוגה חיה בדפדפן
```
python3 n6_bridge_start.py                                   # 1. מפעיל את השולח על ה-N6
./bridge_rx /dev/serial/by-id/usb-MicroPython* -o out/ > stats.txt &   # 2. מקלט
python3 bridge_view.py out/ --port 8090 --stats stats.txt    # 3. תצוגה: http://<jetson>:8090
```
(`bridge_view.py` קורא רק את מה ש-`bridge_rx` כתב — אין קורא שני על ה-USB. `out/` גדל ~10 MB/דקה — לנקות.)

## מה נמדד חי (18.8.2026, אחרי תיקון ה-gc + טבעת ה-IMU)
- 190 ש' רצופות: **0 פריימים אבודים, 0 CRC שגוי, 0 resync**, תרמי 8.6 Hz, RGB 8.6 Hz, **IMU 200.0 Hz בדיוק**, ~228 KB/s.
- התקיעה של ~4 ש' כל ~45 ש' מ-17.8 **נעלמה** — השורש היה `gc.collect()` על ה-N6 (~1 ש', הורג את ה-Lepton), שנגרם מזבל של ~60 KB לפריים בשולח. התיקון: שליחה בלי העתקות (`_send` כותב כותרת ואז payload במקום, IMU נארז לחוצץ קבוע).
- ה-IMU היה 148 Hz אחרי התיקון הראשון: `pack_records` החזיק `busy` לאורך כל לולאת האריזה (~30 ms לפריים = 6 דגימות אבודות). עכשיו הטיימר ממשיך לדגום בזמן האריזה, וקטע קריטי יש רק ב-`_compact` (העברת הדגימות החדשות לתחילת הטבעת).
- אחרי Ctrl-C לשולח ישן הטיימר שלו ממשיך לרוץ ומרעיב את ה-REPL (תווים נבלעים, ה-`OK` מגיע כ-`K`) — המשגר עושה עכשיו soft-reset (Ctrl-B, Ctrl-D) לפני הדחיפה.
- נשאר: פער-קריאה בודד של ~1.8 ש' בצד המחשב (`max_read_gap`) — **בלי** אובדן נתונים ובלי חור ב-IMU (הלוח מחכה, הטבעת סופגת ~5 ש').
- ההחזקות של יעל: `imu_holds.py` על ההקלטה הזאת מצא רק החזקות עם הטיה זהה (הלוח לא הוזז) ודיווח נכון "NOT enough" — וזיהה נכון נגיעות אמיתיות במתקן כתנועה.

## מה נמדד חי (17.8.2026, ג'ייסון ↔ N6 אמיתי)
- **תרמי 8.6 Hz · RGB 8.7 Hz · IMU ~190 Hz · ~190 KB/s**, אפס אובדן בצד השולח, אפס CRC שגוי — במצב יציב.
- IMU אומת: |a| = 1002 mg במנוחה, ציר **X** מצביע לכובד כשהלוח מונח כרגיל.
- הקושחה (MicroPython 1.28) בלי `pyb.USB_VCP` — כותבים דרך `sys.stdout.buffer`; המקלט **חייב להרים DTR/RTS** (בלי זה 2.8 Hz + זבל).
- **תקיעת USB של המחשב ~3.9 ש' כל ~30–60 ש'** (`max_read_gap`) — הלוח נחסם, וביציאה מהתקיעה אובד בלוק אחד של 1,024 B (= פריים תרמי אחד, מדווח כ-bad_crc+gap). לא הקוד, לא הדיסק, לא עומס — חשוד: ניהול צריכת חשמל של USB/מעבד ב-Jetson (דורש sudo: `journalctl -k`, hub power/control, nvpmodel).
- בזמן תקיעה כזאת טיימר-התוכנה של ה-IMU לא רץ (הלוח חסום בכתיבה) — הדגימות פשוט לא נלקחות; החור נראה בחותמות הזמן. חומרה: זה מגבלת `machine.Timer` הרך.

## מה עוד לא
- חותמת הזמן היא `ticks_us` (גולשת כל 17.9 דק'; המקלט פורש). המעבר ל-TIM2 = שינוי `ts_src` בלבד.
- החיישן עצמו מתעדכן ~50–60 Hz; דגימה ב-200 Hz נותנת כפילויות (לא מזיק, אפשר להוריד ל-100).
- מסירה חיה להיתוך (socket / shared memory) — כרגע המקלט כותב לדיסק.
- ה-N6 יכול להיות תפוס ע"י תצוגה אחרת (`fuser /dev/ttyACM0`) — רק תהליך אחד קורא מהיציאה.
